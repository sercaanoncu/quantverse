# QuantVerse v2 Visual Output Audit

## Scope

This audit governs the QuantVerse v2 visual portfolio analytics layer. The layer
creates chart-ready evidence tables for the existing public-data research
pipeline. It does not add portfolio models, change the final model selection
logic, or convert research output into investment advice.

The current final public-data research model is preserved as **HRP** unless a
methodology audit proves that selection invalid. Equal Weight remains the
benchmark, not an automatic winner.

## Methodology Source Basis

The validation standard is grounded in the user's local methodology book
library referenced by the project context:

- Daniel P. Palomar, portfolio optimization: portfolio constraints, HRP,
  risk-based allocation, optimizer fragility and covariance risk.
- Thomas A. Severini, financial statistics: simple/log return separation,
  variance, sampling error and distributional assumptions.
- Samit Ahlawat, quantitative finance methods: risk metrics, regression,
  model selection and metric discipline.
- Machine Learning for Algorithmic Trading: walk-forward validation, leakage,
  transaction costs, random benchmarks and survivorship-bias caution.
- Machine Learning in Finance: forecasting limits, stationarity, GARCH/PCA
  context, governance and diagnostic-versus-promotable ML.
- Isaiah Hull, Machine Learning for Economics and Finance: econometric
  validation, simulation and model interpretation.
- An Introduction to Statistical Learning: train/test discipline, metric
  matching, overfitting and benchmark comparison.
- Quantitative Economics with Python: simulation, dynamic interpretation and
  economic reasoning.

No long book passages are reproduced. The books are used as methodology basis
for validation rules.

## Visual Analytics Output Contract

Every chart-ready CSV must include:

- what was computed,
- formula or method,
- source basis,
- why it is valid,
- what can make it invalid,
- how it was tested,
- whether the output is promoted, diagnostic, blocked, or rejected.

The concrete outputs are generated by
`scripts/build_quantverse_v2_visual_analytics.py` from existing evidence under
`data/processed/`.

## Chart Audit Matrix

| Chart output | What was computed | Formula or method | Why valid | Invalidation condition | Validator check |
|---|---|---|---|---|---|
| `quantverse_v2_visual_equity_curve.csv` | Final model cumulative wealth curve | `equity_t = prod(1 + r_t)`, normalized so first point equals `1.0` | Simple returns aggregate linearly across weights for one period; wealth compounding is the correct visual for realized portfolio path | First value is not exactly `1.0`, returns are not daily simple returns, or missing returns are silently treated as performance | `equity_curve_starts_at_one` |
| `quantverse_v2_visual_drawdown_curve.csv` | Final model drawdown path | `drawdown_t = equity_t / running_max(equity_t) - 1` | Drawdown is a downside path metric and must be non-positive | Any drawdown is positive, equity curve is malformed, or peaks are computed with future information | `drawdown_non_positive` |
| `quantverse_v2_visual_model_risk_return.csv` | Model risk-return comparison | x-axis is annualized volatility; y-axis is annualized return | Risk-return plots are interpretable only when risk is on x-axis and return is on y-axis | Axes are reversed, in-sample metrics are mislabeled as OOS, or extreme metrics are displayed as success without warning | `risk_return_axes_correct` |
| `quantverse_v2_visual_forecast_error.csv` | Forecast error versus random-walk baseline | Compare model MAE to random-walk MAE by horizon | A forecast is not useful unless it beats a defensible naive baseline under the same target scale | Missing random-walk comparator, misaligned horizon, wrong error unit, or forecast treated as allocation proof | `forecast_compares_random_walk` |
| `quantverse_v2_visual_random_benchmark.csv` | Random portfolio Sharpe distribution | Histogram of random portfolio Sharpe values plus final model percentile | Random portfolios provide benchmark context for optimization and selection robustness | Distribution is degenerate, constraints differ from candidate, or percentile is presented as future proof | `random_benchmark_not_degenerate` |
| `quantverse_v2_visual_exposure.csv` | Region, listing-country, issuer-country, economic-country, currency, exchange, sector, industry and sleeve exposures | Group final weights by exposure bucket; each exposure type must sum to `1.0` | Portfolio exposures must reconcile to the same total capital base, while listing venue, issuer domicile and economic risk remain separate concepts | Exposure totals do not sum to one, metadata mapping is missing, ADR/foreign issuer exposure is collapsed into listing country, or currency/region concentration is hidden | `exposure_sums_to_one` |
| `quantverse_v2_visual_top_holdings.csv` | Top final holdings by weight | Sort final model weights descending | Concentration must be visible before interpreting performance | Negative weights appear in a long-only output, cap breaches are hidden, or only top holdings are shown without full weights path | `top_holdings_non_negative` |

## Interpretation Standard

The visual layer must not be a raw table dump. PDF, HTML and Excel surfaces must
include interpretation, limitation and decision impact for each major chart.

Required visual conclusions:

- HRP is the current public-data research final model.
- HRP is selected over Equal Weight because the current evidence layer favors
  risk-adjusted, drawdown, CVaR, turnover, robustness and random-benchmark gates,
  while still keeping the global master promotion decision as **not promoted**.
- Equal Weight remains a mandatory benchmark.
- Forecast outputs remain diagnostic unless they improve net portfolio decision
  quality after costs, risk and robustness checks.
- Random benchmark percentile is context, not proof of future superiority.
- Exposure concentration is an economic interpretation and governance issue,
  not a cosmetic chart.
- Listing exposure means where the ticker trades; issuer exposure means company
  domicile; economic exposure means business-risk geography only when explicit
  metadata exists. Economic exposure must remain `missing` when it is not
  sourced.
- ADR and foreign issuer tickers must not become United States issuer exposure
  merely because they trade on a US venue in USD.

## Permanent Failure Conditions

The visual layer fails if any of the following occurs:

- equity curve does not start at `1.0`,
- drawdown is positive,
- risk-return axes are reversed,
- forecast error has no random-walk comparator,
- random portfolio benchmark is degenerate,
- exposure chart weights do not sum to `1.0` within tolerance,
- sector or issuer-country coverage is zero while the artifact claims ordinary
  metadata success,
- listing-country exposure is displayed as issuer-country or economic-country
  exposure without explicit metadata,
- PDF or Excel presents raw tables without method, interpretation and limits,
- model output is promoted while public-data limitations remain unresolved,
- visual design hides an economically meaningful red flag.

## Status

This sprint adds a chart-ready visual analytics layer and validator checks. It
does not alter the HRP final public-data research model, portfolio construction
logic, source universe, forecasts, or promotion gate.
